Unique key column pairs

Multiple pairs form one composite key. Each nonblank key must be unique within its table. Review the suggested mappings before comparing.

Fields to compare

Only selected fields determine changed versus unchanged. No selected fields means a key-membership comparison. Values are compared exactly.

Key matching options

Exact key matching is the default. Normalization affects matching only; raw keys and field values remain in the report. Any empty key component is unresolved. Duplicate keys in either table make all associated rows on both sides unresolved. Text IDs such as 0 and 001 stay distinct.

Use it for your next export

  1. Keep both originals. Use UTF-8 CSV/TSV, with a header row; XLSX input is not supported.
  2. Choose an ID that identifies one record, or map several columns as a composite key. Review every suggested column pair.
  3. Select the fields to compare. Only those fields determine changed versus unchanged; 12.50 and 12.5 differ as text.
  4. Resolve blank or duplicate keys before drawing conclusions. Review the full report before updating another system.

Limits: 5 MiB per input; 20,000 data records and 250,000 cells combined. This is an interactive file comparison, not a scheduled sync or an automatic repair. CSV reports cannot force Excel to keep IDs as text. Preserve a CSV report as text in XLSX ↗

Worked example

The worked order exports reorder both columns and rows. Order 00102 changes total from 85.00 to 90.00, 00101 is removed, 00105 is added and 00103 plus the literal ID 0 are unchanged. The two earlier 00104 records, their later match and a blank earlier key are four unresolved source records.

Method and limits

Comparison is based on the selected fields, not every cell automatically. Values compare as text: 12.50 differs from 12.5. Key normalization is optional and can create collisions. Ambiguous keys are never guessed or expanded into many-to-many rows. Combined inputs are limited to 20,000 records and 250,000 cells.
