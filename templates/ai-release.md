# AI 서비스 실패·재시도 점검표
회몬 · JH Soft Labs | 공개용 v1.0 | 2026-09-13
관련 기록: https://jhsoftlabs.com/stories/ai-retry-safety.html

진단 안정화 작업을 바탕으로 새로 정리한 공개용 점검 양식입니다.
개인·팀 작업에 맞게 복사해 채워 쓰세요.
특정 서비스의 운영 코드·SQL이 아니며 보안 감사나 무장애 보증을 대신하지 않습니다.

## 사용 순서
1. 성공할 때 함께 보존돼야 할 상태를 적습니다.
2. 격리된 테스트 환경에서 실패 상황을 하나씩 만듭니다.
3. 테스트 결과와 실제 운영 적용 여부를 별도로 기록합니다.

## 1. 이번 변경의 경계
- 기능 / 담당자 / 확인일:
- 사용자에게 성공이란:
- 함께 확정해야 하는 데이터:
- 같은 요청을 다시 구분하는 기준:
- 새로운 작업으로 처리할 조건:
- 데이터 보관·삭제 범위:
- 외부 AI 호출 / 비용이 발생하는 지점:
- 이번에 바꾸지 않을 기능:
- 테스트 환경과 합성 데이터:
- 운영 반영 승인 / 별도 확인이 필요한 사항:

## 2. 시나리오별 검증표
각 항목에 예상 결과, 실제 결과, 근거, [통과 / 실패 / 미확인 / 해당 없음]을 적습니다.
'해당 없음'에는 이유를 남깁니다.

### 같은 요청을 두 번 제출
- 예상: 같은 작업의 중복 실행과 중복 사용량 반영을 막음
- 실제 결과:
- 확인 근거 / 상태:

### 마지막 남은 사용 횟수에 동시 요청
- 예상: 허용량을 초과해 승인하지 않음
- 실제 결과:
- 확인 근거 / 상태:

### 결과 저장 도중 오류
- 예상: 결과와 사용량 중 일부만 확정되지 않음
- 실제 결과:
- 확인 근거 / 상태:

### 저장은 완료됐지만 응답 유실
- 예상: 다시 확인할 때 기존 완료 결과를 유지
- 실제 결과:
- 확인 근거 / 상태:

### 완료 뒤 늦게 도착한 실패 처리
- 예상: 이미 완료된 결과를 실패로 덮어쓰지 않음
- 실제 결과:
- 확인 근거 / 상태:

### 작업 중단과 시간 만료
- 예상: 끝없는 로딩 대신 상태 안내와 안전한 재시도 경로 제공
- 실제 결과:
- 확인 근거 / 상태:

### 비로그인 결과를 계정으로 이전
- 예상: 중복 이전으로 결과나 사용량이 반복 반영되지 않음
- 실제 결과:
- 확인 근거 / 상태:

## 3. 운영 반영 전후
- [ ] 합성 데이터로 검증했고 사용자 원문은 사용하지 않았다.
- [ ] 테스트 실패가 기존 데이터를 변경하지 않는다.
- [ ] 테스트 통과와 운영 반영 완료를 구분했다.
- [ ] 사용자 권한으로 허용되지 않은 변경을 할 수 없는지 검증했다.
- [ ] 복구·재시도 화면을 실제 사용자 경로에서 확인했다.
- [ ] 기존 데이터 보존 조건을 확인했다.
- [ ] 안전한 되돌리기 조건과 담당자를 적었다.
- [ ] 비밀키·접속 정보·사용자 답변이 보고서에 없다.
- [ ] 비용 상한과 보관·삭제 정책은 별도 검토 여부를 기록했다.

## 4. 인수인계 한 장
- 준비한 코드 / 검증한 버전:
- 확인한 테스트와 한계:
- 운영 적용 상태: [미적용 / 적용 중 / 적용 확인]
- 운영 적용일 / 확인 근거:
- 남은 실패 / 미확인 항목:
- 문제가 생기면 먼저 볼 상태:
- 안전한 복구 조건:
- 다음 담당자가 할 한 가지:
- 변경하면 안 되는 항목:

운영 환경에 장애를 직접 주입하지 마세요.
권한과 복구 계획을 확인한 격리 환경에서 검증하고, 실제 적용은 별도 절차로 다루세요.
