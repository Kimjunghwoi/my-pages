# 실제 검증 기록과 브라우저 점검 도구

## 화면과 성공 기준

- 홈: 대표 프로젝트 3개를 최상단에 유지하고 실험 기록에 실제 Excel 검증 후속 글을 추천한다. 예전 글과 외부 링크는 보존한다.
- `stories/excel-native-checks.html`: 긴 ID 보존 실패, 검증한 대체 경로, 미해결 원인을 구분한다. 독자는 자신의 가이드 점검으로 이동할 수 있다.
- `tools/release-check/`: AI 서비스 / 웹사이트 / 실무 가이드 중 하나를 선택하고 6개 항목의 상태를 분류해 Markdown 기록을 내려받는다. 자동 검사나 안전 점수로 표시하지 않는다.
- 템플릿 목록: 기존 다운로드 3종과 전체 미리보기를 유지하며 실전 점검 도구로 연결한다.
- 320/390/768/1366px, 키보드 입력, 초기화 취소·확인, 다운로드와 fallback을 점검한다.

## 데이터 모델

- Checklist: 공개 고정 `ai`, `site`, `guide` 식별자, 제목, 설명, 항목 6개, 관련 글·템플릿.
- Item: 문서 안의 고유 ID, 제목, 확인 방법, 상태 `unknown/pass/recheck/na`.
- 선택 상태는 탭 메모리에만 있다. 자유 입력, 사용자·고객 파일 업로드, 영구 저장은 없다.
- Article: 새 공개용 원고와 합성 ID 비교. 개인 이력서 문서·채팅 원본·계정·예산·사용자 데이터는 포함하지 않는다.

## API 계약

신규 서버 API·인증·DB·키·쿠키 없음. 상태 선택은 외부로 전송하지 않는다. 다운로드는 브라우저 Blob으로 만들며, 실패 시 같은 결과를 읽기 전용 텍스트로 보여준다. 복사는 Clipboard API 실패 시 텍스트를 직접 선택할 수 있도록 안내한다.

## 상태 소유

- 홈 검색과 URL은 기존 `script.js`만 담당한다.
- 도구의 `checklist.js`는 현재 주제, 항목별 선택, 집계·내보내기·초기화 확인을 담당한다. HTML이 항목의 원본이다.
- 주제 전환은 다른 주제 선택값을 유지한다. 현재 주제만 초기화하며 인라인 확인·취소를 제공한다.
- URL은 주제만 `?kind=guide`로 받는다. 선택값은 URL·로그·저장소에 기록하지 않는다.
- JavaScript 미사용 시 모든 점검 항목과 관련 템플릿을 읽을 수 있고 작동하지 않는 제어부는 숨긴다.

## 외부 연동

| 대상 | 변경 | 실패 시 |
| --- | --- | --- |
| 기존 Vercel 분석 | 일반 페이지뷰 유지, 항목 상태·사용자 정의 이벤트 추가 없음 | 도구 기능은 별개 |
| 기존 Google Fonts | 변경 없음 | 기존 글꼴 대체 |
| 하위 서비스 | 일반 링크만 유지 | 홈페이지와 독립 |
| Clipboard / Blob | 브라우저 로컬 출력 | 읽기 전용 결과를 선택해 사용할 수 있음 |
| Vercel 배포 | 이번에는 로컬 구현·검증, 별도 배포 없음 | 기존 운영 유지 |

## 릴리즈 체크

- 새 환경 변수, DNS, SMTP, 운영 SQL, 결제·요금제 변경 없음.
- 실제 Excel 관측은 Version 16.0 / Build 5569.0, 합성 자료로 범위를 한정한다. 성공한 가져오기 경로와 미해결 OpenText를 구분한다.
- 기존 기록/검색/템플릿 계약, 새 상태 전환·경계·내보내기 검사, 문법·메타데이터·사이트맵 검사를 수행한다.
- 공개 HTML 검사에 `tools` 하위 디렉터리도 포함한다. 내부 문서는 계속 배포에서 제외한다.
- 운영 승인 후 배포한다면 이전 정상 Vercel 배포로 복구할 수 있다. DB 변경은 없어 별도 데이터 복구 없음.
- 검증 결과는 이 문서 말미에 추가한다. 실제 브라우저와 DOM 어댑터 검사를 구분한다.

## 구현·검증 결과

- 새 실험 기록 1편과 브라우저 점검 도구 1개를 추가했다. 기존 대표 프로젝트 3개, 외부 링크 19개, 템플릿 3종의 본문·다운로드는 유지했다. 자료 목록은 총 28개다.
- `node --test tests/*.test.mjs`: 45개 통과. 실제 HTML에서 항목을 읽는 DOM 어댑터로 상태·초기화·내보내기·오류 대체·초기값 복원을 검사했다. 정적 계약과 실제 브라우저 검증을 혼동하지 않는다.
- 홈페이지·템플릿·새 글·도구를 320/390/768/1366px에서 점검했다. 가로 넘침을 발견하지 않았고, 새 글의 ID 비교 도해는 모바일에서 세로 배치된다.
- 실제 인앱 브라우저에서 select 키보드 조작, 작업 유형별 선택 유지, 초기화 취소·확인, 홈의 기록 5개·양식/도구 4개 필터를 확인했다.
- 도구 소개를 압축하고 모바일에서 집계·내보내기 바로가기를 제공했다. 대표 프로젝트가 먼저 읽히는 홈 구조는 유지했다.
- 로컬 HTTP로 홈·템플릿·새 글·도구·새 JS/CSS·사이트맵·기존 양식 8개 경로의 200 및 본문을 확인했다.
- 다운로드는 Blob 생성·내용·파일명·URL 회수를 자동 검사했다. 인앱 브라우저에서는 다운로드 완료 이벤트가 관측되지 않아 실제 파일 저장을 검증 완료로 주장하지 않는다.
- Clipboard API의 성공 응답과 화면 안내는 있었으나 브라우저 연결 도구로 읽은 클립보드가 비어 있어 실제 OS 클립보드 전달은 미확인이다. 실패 시 fallback은 자동 검사했고, API와 무관한 텍스트 전체 선택·6개 항목·선택 상태·readonly는 실제 화면에서 확인했다.
- JavaScript 미사용 대체 내용은 정적 HTML 계약 검사다. 스크린리더 실기·200% 확대·다른 브라우저 엔진의 출력 기능은 후속 검증 대상이다.
- Git 커밋·푸시·Vercel 배포·DNS·DB·하위 서비스 변경은 하지 않았다. 개인 이력서 문서와 내부 출처는 공개 파일에 포함하지 않았다.
