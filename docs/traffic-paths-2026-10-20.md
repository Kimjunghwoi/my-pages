# 검색·공유 경로 확장

## 구조와 범위

기존 HTML/CSS/vanilla JavaScript와 Cloudflare Pages Git 배포를 유지한다. 승인된 추가 작업은 검색 제목 구체화, 주제별 공유 이미지와 공유 기능, 관련 자료 연결, 한국어 가이드 두 편, RSS, Naver 수집 상태 확인과 SNS 게시용 자료 준비다. 공개 SNS 게시·외부 서비스 소스 수정·광고 활성화·새로운 추적은 포함하지 않는다.

- 화면: 기존 글과 프로젝트를 보존한다. 새 가이드는 `data-guides/` 아래에 두고 홈·가이드 목록·자료 검색·사이트맵에 연결한다. 글 말미의 기존 다음 글 경로를 유지하면서 관련 글/실습/도구를 구분한다.
- 공유: `sharing.js`는 정규 URL만 복사하거나 브라우저 기본 공유로 넘긴다. 검색어·현재 query·선택 상태를 공유하지 않는다. 취소와 실패를 구분하고, 실패하면 읽기 전용 URL을 직접 선택할 수 있게 한다. JavaScript 없이도 정규 링크와 RSS는 읽을 수 있다.
- 데이터: 서버 API·DB·로그인·쿠키·사용자 정의 분석 이벤트를 추가하지 않는다. 공유 상태는 현재 페이지 메모리만 사용한다. SNS 초안과 계정 관측은 `outputs/`에 두어 Git·웹에서 제외한다.
- 피드: `scripts/build-feed.mjs`는 명시적으로 허용한 자체 기사만 읽고 본문·실제 게시/수정일·절대 정규 주소를 RSS 2.0으로 만든다. 외부 Notion·비공개 문서·계정 정보는 포함하지 않는다. 빌드에서 피드 최신화를 검사한다.
- 미디어: `scripts/render-share-cards.mjs`의 주제별 벡터 설명을 PNG로 렌더링한다. 실제 앱 화면이나 이용 성과로 가장하지 않는다. PNG는 저장소에 포함해 Pages 빌드에 이미지 처리 런타임을 요구하지 않는다.
- 검증: 합성 예제의 문자열·자료형·정밀도 차이는 가능한 실제 Excel 엔진으로 확인하되 UI 조작·모든 버전·왕복 저장 검증으로 확대하지 않는다. 자동 테스트, 공개 HTTP, 브라우저 화면과 실제 공유/OS 클립보드 검증을 구분한다.

## 유지해야 할 계약

프로젝트 네 개, 기존 자료 38개와 앵커, 검색·필터·뒤로가기, AdSense 소유 확인과 ads.txt, 광고 비활성 상태를 유지한다. 신규 한국어 글 두 편이 추가되므로 자료 목록은 40개가 된다. 새 글 작성일만 실제 공개일로 설정하며 기존 글의 게시일을 바꾸지 않는다. 기존 글 본문에 새로운 실행 성과를 만들지 않는다.

검색 제목 변경은 원문 제목이 추상적인 대표 개발기록 세 편으로 한정하고 변경 전후를 남긴다. 다수 기능·콘텐츠를 같은 배포에서 바꾸므로 이후 지표 변화가 어느 요소 때문인지 인과를 확정할 수 없다. 검색 유입과 AdSense 승인은 별도다.

## 구현과 검증

- 한국어 가이드 두 편: TRIM/NBSP와 16자리 이상 식별자. 기존 가이드 4편과 개발기록 10편은 보존했고 자료 검색은 40개가 됐다.
- 검색 제목은 `ai-retry-safety`(AI API 재시도와 중복 저장 방지), `excel-native-checks`(Excel 긴 ID 손상과 필터 검증 기록), `column-harbor`(CSV 원본 보존을 위한 브라우저 도구 설계) 세 편만 구체화했다. 본문 제목과 원래 게시일은 유지한다.
- 공유 이미지 11종은 1200×630 PNG이며 SVG·렌더러를 함께 보관한다. CI/Pages에서 이미지 패키지 설치는 필요하지 않다. 대표 글·템플릿·게임의 Open Graph/Twitter/구조화 이미지가 해당 파일을 가리킨다.
- 16편의 전체 본문을 RSS로 만들고 모든 자체 읽기 경로에 구독 주소를 연결했다. 허용 목록, 원래 게시일, 전체 본문 끝, 절대 정규 링크, 비공개/활성 콘텐츠 제외, XML 파싱을 확인했다. `feed.xml`은 16개 item이다. 날짜만 있는 원문의 RSS 시각은 00:00 KST로 정규화하며 실제 게시 시각을 복원한 것이 아니다.
- 실제 Excel 16.0 build 5574.0의 별도 통합문서에서 36개 비교가 통과했다. 일반 공백 17→12, NBSP 14→14→12, 좁은 NBSP 7→7→7, 숫자 문자열의 끝자리 손상과 길이 16/16·EXACT FALSE를 확인했다. 결과는 `docs/traffic-excel-evidence-2026-10-20.json`에 있다. UI·가져오기·왕복 저장·다른 버전 검증은 아니다.
- `node scripts/verify-pages.mjs`: 테스트 97개 통과. Pages 출력은 87파일, 8,616,387bytes다. 신규 공유 모듈의 정상/실패/취소/중복 작동/수동 선택/정규 URL 경계를 자동 검사했다. 사용자 입력이나 새 이벤트 수집은 없다.
- 브라우저에서 새 글 두 편·가이드 목록·홈을 320/390/768/1280px로 확인했다. 16가지 조합 모두 페이지 가로 넘침이 없었다. 넓은 표는 이름 있는 키보드 진입 영역 안에서만 가로 스크롤된다. 수식 내부의 공백이 합쳐지지 않도록 inline code 표시도 보완했다.
- 링크 복사 API가 성공 응답을 반환했지만 인앱 브라우저 연결의 clipboard 읽기와 일치하지 않았다. OS 클립보드 전달을 검증 완료로 주장하지 않는다. 그래서 API와 별개인 `주소 직접 선택` 버튼을 추가했다. 실제 모바일 브라우저에서 readonly URL의 전체 52자 선택·초점·표시를 확인했다. 브라우저 기본 공유의 성공/취소/실패는 모듈 자동 검사이며 실제 OS 수신자를 선택해 전송하지 않았다.
- 홈 검색: TRIM은 새 한국어 글과 기존 EN 자료 두 개, 16자리는 새 한국어 글 한 개가 표시됐다. 초기화와 기존 필터 동작을 유지한다. 광고는 여전히 비활성이다.
- Naver: 사용자가 직접 로그인한 후 루트 도메인의 기존 소유 등록, 인증서·HTTPS 리다이렉션 정상, robots에서 sitemap 발견을 확인했다. 하지만 제출된 sitemap/RSS 목록은 둘 다 비어 있었다. 노출/클릭 화면은 `정보가 없습니다`였으며 이를 트래픽 0으로 단정하지 않는다. 공개 배포 검증 후 누락된 두 주소를 등록할 예정이다. 아직 검색 반영·성과가 확인된 것은 아니다.
- SNS 게시 초안은 `outputs/reviews/traffic-2026-10-20/SOCIAL-DRAFTS.md`에만 있다. 실제 게시·발송하지 않았다.

브라우저 모사 viewport는 실제 휴대전화·모든 보조기기·다른 엔진 검증을 대신하지 않는다. 앱 변경과 검색 노출 증가, 광고 승인을 혼동하지 않는다.
