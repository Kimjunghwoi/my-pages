# 독자 진입부와 실제 Excel 근거 보강

## 범위

- 메인의 한국어 문제 해결 가이드 네 편을 프로젝트보다 먼저 배치했다. 프로젝트 세 개, 기존 콘텐츠와 URL, 외부 서비스 링크는 유지했다.
- 데이터 가이드 목록의 오래된 영문 39편 안내를 개수 없는 표현으로 교체했다.
- CSV 한 열 문제와 앞자리 0 가이드에 실제 Excel QueryTables 가져오기 결과, 자료형 대조, 독자가 실행할 수식을 추가했다. 글과 사이트맵의 수정일만 갱신했으며 최초 게시일은 유지했다.
- 새 추적 코드, 사용자 파일 수집, DNS 변경, 광고 설정 변경은 없다. AdSense 승인이나 원인 해결을 보장하는 변경이 아니다.

## 실제 검증

`python scripts/verify-excel-import.py`는 별도 Excel 인스턴스의 임시 통합문서에서 공개 합성 CSV를 읽는다. 원본과 사용자 통합문서를 수정하거나 저장하지 않는다. Windows, Excel, pywin32가 필요하다.

성공한 경로는 QueryTables TEXT, UTF-8, 세미콜론, 큰따옴표 한정자, 소수점 점, 열별 명시적 자료형이다. Excel 16.0 build 5569.0에서 27개 검증이 통과했다. 결과는 `excel-import-evidence-2026-10-05.json`에 보존했다.

- General은 첫 ID를 숫자 123으로, Text는 문자열 00123으로 읽었다.
- 따옴표 안 쉼표/세미콜론은 각각 설명 안에 보존됐으며 가격은 12.5와 8이었다.
- 00000 서식 적용 후 표시 문자열은 00123이지만 내부 값은 숫자 123이었다.
- 게시한 ISTEXT/LEN/EXACT 수식을 실제 엔진에서 실행해 두 자료형의 예상 결과를 대조했다.

초기 실패도 성공 결과와 구분한다. PowerShell OpenText 호출은 COM 예외, Python OpenText 시도는 예상 열 개수 불일치, TextToColumns 시도는 Text FieldInfo를 전달했음에도 숫자 반환으로 실패했다. 자동화 인수 전달/해당 경로의 원인은 확정하지 않았다. 이를 Excel 메뉴 자체의 버그라고 주장하지 않는다. 기존 CSV 프로젝트의 역사적 디버깅 기록에서도 유사한 미해결 현상이 있어 검증된 QueryTables 방식으로 한정했다.

Power Query 및 리본/팝업 UI 클릭, 모든 버전, CSV 왕복 저장을 검증한 것으로 표시하지 않는다. 해당 제한을 공개 글에도 명시했다.

## 회귀 및 공개 범위

- Node 검증: 65개 테스트, 링크/앵커/메타데이터/공개 파일 허용 목록 검사 통과.
- 브라우저: 데스크톱 화면, 390px 모바일 메인과 가이드 이동, 390px/320px 가이드의 문서 가로 넘침 없음 확인.
- 빌드: 공개 48개 파일. docs/tests/scripts와 네이티브 실행 보고서는 웹 배포에 포함되지 않는다.
- 별도 진단 메모 `adsense-diagnosis-2026-10-05.md`는 비공개 계정 관측을 포함하므로 이번 공개 Git 커밋에 넣지 않는다.

## 배포와 복구

Cloudflare Pages의 기존 main Git integration과 `node scripts/verify-pages.mjs`를 사용한다. 환경변수나 DB 변경은 없다. 배포 후 메인 순서, 두 글의 실제 검증 절, 오래된 수치 제거, sitemap/ads.txt와 404를 확인한다.

문제가 있으면 이번 코드 커밋을 revert해 main에 반영한다. DNS나 다른 프로젝트를 바꾸지 않는다. 공개 확인 결과는 작업 완료 응답에 별도로 기록한다.
