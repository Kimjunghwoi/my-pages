# 회몬 홈페이지 발전 방향과 개발자 사이트 벤치마크

조사일: 2026-09-13. 대상: [JH Soft Labs](https://jhsoftlabs.com/). 기준 코드: `2283743`.

## 결론

지금의 밝은 종이 질감, 녹색 포인트, 회몬 캐릭터, 프로젝트 우선 구성을 유지하는 편이 좋다. 다음 단계는 전면 리디자인보다 **프로젝트를 더 빨리 이해하고, 작게 체험하고, 만든 사람을 신뢰하게 하는 것**이다.

회몬 홈페이지는 취업용 이력서만도, 기술 블로그만도 아니다. 서로 다른 세 서비스와 콘텐츠를 연결하는 개발자·메이커의 홈이다. 따라서 유명한 포트폴리오의 색상이나 레이아웃 전체를 복제하지 않고, 목적에 맞는 장치만 가져온다.

이번에는 공개 사이트·수상 기록·저장소·커뮤니티 반응과 현재 코드/화면을 조사했다. 운영 코드, DNS, 분석 설정, 배포는 변경하지 않았다. 방문자 분석 대시보드나 실제 매출·전환 자료는 열람하지 않았으므로 아래 기대 효과는 검증할 가설이다.

측정은 인앱브라우저의 실제 `innerWidth/innerHeight`, 스크롤 0 상태를 기준으로 했다. 위 두 화면에서 문서 가로 넘침은 없었다. 첫 화면 아래에 버튼이 있다는 사실 자체를 기능 버그나 전환 하락의 증거로 보지는 않는다. 작은 글씨 역시 크기만으로 접근성 표준 위반이라고 단정하지 않는다. 이번 조사는 전체 접근성·성능 감사를 대체하지 않는다.

## 반응의 근거가 있는 벤치마크

아래 숫자는 확인 당시의 공개 표시 값이다. GitHub 관심도, 콘텐츠 반응, 디자인 수상은 서로 다른 지표이며 방문자 수·매출·문의 전환율로 환산할 수 없다.

### 1. Brittany Chiang: 결과물을 근거와 함께 보여주기

[현재 사이트](https://brittanychiang.com/)는 짧은 정체성 소개와 섹션 탐색을 제공하고, 프로젝트마다 목적·기술·결과물을 연결한다. 모든 작업은 별도 아카이브로 분리한다.

관심도 근거는 이전 v4 사이트의 [공개 저장소](https://github.com/bchiang7/v4)에 표시된 약 8.3k stars, 4.2k forks다. 현재 디자인 자체의 성과 수치가 아니라, 이전 개인 사이트 구현에 대한 관심이다.

**가져올 것:** 프로젝트마다 '누구의 어떤 문제를 해결하는지 → 확인 가능한 결과물 → 직접 사용'을 연결한다. 회몬에게는 기술 배지 여러 개보다 실제 진단 예시나 홍보물, CSV 위험 예시가 더 중요하다.

**가져오지 않을 것:** 남색 배경과 민트 포인트, 이력서 중심의 좌우 분할 레이아웃 전체. 원작의 코드·이미지·글을 복제하는 것이 아니라 정보 구성 원칙을 참고한다.

### 2. Anthony Fu: 지금 집중하는 작업과 전체 목록을 구분하기

[프로젝트 페이지](https://antfu.me/projects)는 'Current Focus'를 먼저 보여주고, 나머지를 분야별 목록으로 정리한다. 최근 릴리즈로 가는 별도 경로도 있다. 개인 사이트 [저장소](https://github.com/antfu/antfu.me)는 약 1.1k stars, 272 forks다.

**가져올 것:** 현재 운영하는 대표 프로젝트는 짧고 선명하게, 글과 향후 실험은 별도 목록으로. 회몬 홈페이지의 현재 방향과 가장 잘 맞는 참고 사례다. 프로젝트가 늘면 '현재 운영 / 실험 / 종료'를 사실에 맞게 나눌 수 있다.

**가져오지 않을 것:** 프로젝트가 세 개뿐인 지금 수십 개 분류나 복잡한 기술 생태계 목차를 만드는 것. 분류의 수보다 선택 부담을 줄이는 것이 목적이다.

### 3. Josh W. Comeau: 설명 대신 작은 체험을 제공하기

[홈페이지](https://www.joshwcomeau.com/)는 주제별 콘텐츠 탐색을 제공한다. [SVG 경로 가이드](https://www.joshwcomeau.com/svg/interactive-guide-to-paths/)는 코드와 결과, 직접 조작하는 예시를 연결해 설명한다. 해당 글은 2025년 [Hacker News 게시물](https://news.ycombinator.com/item?id=44941605)에서 455 points, 44 comments를 얻었고 설명과 인터랙션에 대한 긍정적인 반응을 확인할 수 있다. 이는 글의 반응이지 홈페이지 전환율은 아니다.

**가져올 것:** CSV의 `00123`이 숫자로 해석될 때와 텍스트로 유지될 때를 버튼 한 번으로 비교하는 예시. 또는 면접 답변의 근거가 부족한 부분과 보완 방향을 짧게 보여주는 비교. '써 보면 이해되는 것'을 한 가지 만든다.

**가져오지 않을 것:** 홈페이지에 세 서비스의 전체 기능을 다시 구현하거나 처음부터 긴 인터랙티브 강좌를 만드는 것. 자동 재생 소리나 과한 장식도 필요 없다.

### 4. Bruno Simon: 사이트 자체가 제작자의 능력을 증명하게 하기

[포트폴리오](https://bruno-simon.com/)는 자동차를 조작하는 3D 공간으로 작업을 탐색하게 한다. [2026 Webby Awards 공식 기록](https://winners.webbyawards.com/2026/websites-and-mobile-sites/features-design/technical-achievement/370083/brunos-portfolio)에서 Technical Achievement의 Webby Winner와 People's Voice Winner를 모두 확인했다.

**가져올 것:** 회몬의 캐릭터와 직접 만든 결과물이 기억에 남게 하는 작은 고유 경험. 예를 들어 예시의 핵심을 짚어 주는 짧은 캐릭터 코멘트는 가능하다. 서비스 사용 경로는 항상 바로 보여야 한다.

**가져오지 않을 것:** 전체 3D 공간, 게임을 해야 열리는 링크, 긴 로딩. Bruno에게는 3D 자체가 전문성의 증거지만, 회몬의 세 서비스를 찾는 방문자에게는 불필요한 장벽이 될 수 있다.

### 5. Bartosz Ciechanowski: 공유할 이유가 있는 독립 콘텐츠 만들기

[Bicycle](https://ciechanow.ski/bicycle/)은 상호작용하는 도해로 원리를 설명한다. 2023년 [Hacker News 게시물](https://news.ycombinator.com/item?id=35343495)은 3,014 points, 399 comments를 기록했다. 최신 유행 사례가 아니라, 설명형 콘텐츠가 큰 관심을 얻은 선행 사례로 참고한다.

**가져올 것:** 'AI를 잘 쓴다'는 소개보다 직접 보여줄 수 있는 글 한 편. 예를 들어 'CSV를 열었을 뿐인데 상품 코드가 달라지는 이유'를 작은 예시와 함께 설명하고 실제 도구로 연결한다.

**가져오지 않을 것:** 높은 조회를 기대하며 대형 시뮬레이션부터 만드는 것. 콘텐츠의 독립적인 쓸모가 먼저다.

### 보조 참고: Lee Robinson

[현재 홈페이지](https://leerob.com/)의 짧은 소개, 확장된 소개, Notes와 Blogs 구분은 간결한 운영 방식의 참고가 된다. 다만 과거 `leerob/site` 주소가 연결되는 [next-mdx-blog 저장소](https://github.com/leerob/next-mdx-blog)의 관심도를 현재 개인 홈페이지의 반응으로 사용하지 않았다. 이 사례는 구조 참고이지 성과 근거가 있는 선정 사례는 아니다.

## 회몬에게 맞는 적용안

### 프로젝트별 체험은 서로 다르게

| 프로젝트 | 작은 체험 | 체험 후 행동 | 반드시 지킬 경계 |
| --- | --- | --- | --- |
| Interviewer Lens | 고정된 답변 예시에서 '보완할 부분'을 눌러 근거·기여도·꼬리질문을 확인 | 내 답변 진단 시작 | 사전 작성 예시임을 표시한다. 점수 상승이나 합격을 보장하지 않는다. 실제 사용자 답변이나 AI 호출을 홈에서 받지 않는다. |
| Deep Constellation | 오픈 홍보 / 시즌 스타일 / 예약 안내 제작 예시를 선택해 크게 보기 | 제작 사례 확인 또는 문의 | AI·가상 매장 예시를 실제 고객 실적이나 시술 결과로 표현하지 않는다. 확대 보기에는 키보드와 닫기 경로를 제공한다. |
| Column Harbor | 고정된 `00123`을 숫자 해석 / 텍스트 유지로 전환해 차이 보기 | 내 CSV 점검하기 | 설명용 시뮬레이션임을 표시한다. 손상된 값의 복구나 자동 수정을 주장하지 않는다. 파일 업로드 없이 동작한다. |

추천 첫 구현은 **Column Harbor의 작은 비교 예시 하나**다. 고정 데이터만으로 핵심 문제를 보여줄 수 있어 비용·개인정보·외부 API 의존성이 적다. 매장 홍보 문의가 최우선 사업 목표라면 Deep Constellation 갤러리를 먼저 만드는 편이 맞다. 세 프로젝트의 체험을 한 번에 늘리지는 않는다.

### 제작기에는 경력보다 판단을 담기

프로젝트별 상세 페이지는 '문제 / 대상 / 실제 결과물 / 주요 선택과 이유 / 현재 한계 / 다음 개선 / 사용 링크' 순서가 좋다. 화면을 길게 늘이는 대신 홈페이지에는 '만든 이야기' 보조 링크만 둔다.

초기 후보 제목은 'CSV 점검기를 서버 업로드 없이 만든 이유', '면접 답변에서 점수보다 약한 근거를 먼저 보여주고 싶은 이유'다. 제목은 제안이며 실제 설계 의도와 일치하는지 코드·제작 기록으로 확인한 뒤 작성한다. 미공개 소스, 고객 데이터, 비용·매출 수치를 임의로 공개하지 않는다.

### 처음 온 사람에게는 읽는 순서를 제안하기

큰 카드 섹션을 또 추가하지 않고 자료 영역 상단의 짧은 텍스트 경로로 제공한다.

- 면접 준비: 팀핏 대비 리스트 → Interviewer Lens → 답변을 다시 점검하기.
- AI 부업: 첫걸음 글 → 1일 차 루틴 → Deep Constellation 제작 예시.
- 데이터 실무: Column Harbor 점검기 → 확인한 위험에 맞는 가이드.

자료의 게시일·수정일은 출처에서 확인한 경우에만 넣는다. 확인되지 않은 날짜 대신 내부 관리용 '링크 확인일'을 별도로 기록할 수 있다. 데이터가 없으면 '인기 글'이 아니라 '처음 읽기 좋은 글'처럼 편집 추천임을 분명히 한다.

## 단계별 체크리스트

작업량은 상대적인 S/M/L이며 일정이나 성과를 보장하는 추정이 아니다. 아래 항목은 아직 구현하지 않았다.

### 1단계: 현재 디자인의 읽기 편의 완성 (S)

- [ ] 중요한 출처·언어·이용 조건의 작은 글씨를 키운다. 그림 속 장식 글자와 실제 안내 문구는 구분한다.
- [ ] 프로젝트 이름과 용도가 그림보다 먼저 전달되도록 배치를 조정한다. 기존 캐릭터·색감·대표 세 프로젝트 구조를 보존한다.
- [ ] 390×844, 1366×768에서 첫 프로젝트 이름·용도의 초기 노출을 확인한다. 모든 CTA를 첫 화면에 강제로 넣는 것을 목표로 삼지는 않는다.
- [ ] 320/390/768/1024/1440px, 200% 확대, 키보드 이동, 긴 제목, 글꼴 로딩 실패에서 넘침과 가림을 확인한다.
- [ ] 검색, 필터 URL, 뒤로가기, 더 보기, 기존 앵커와 모든 외부 링크를 회귀 검증한다.

### 2단계: 설명보다 설득력 있는 예시 (M)

- [ ] CSV 비교 예시 하나를 구현하고 '설명용 예시'를 표시한다. 기존 서비스 링크는 항상 접근 가능하게 둔다.
- [ ] 키보드 조작, 결과 상태 안내, 동작 줄이기 설정, JavaScript 미사용 시 대체 설명을 지원한다.
- [ ] 대표 프로젝트 제작기 한 편을 자체 도메인의 정적 페이지로 작성한다. 코드·기록으로 확인한 내용만 사용한다.
- [ ] 제목, 설명, 공유 이미지, canonical, 목록에서의 발견 경로를 함께 점검한다.
- [ ] 대상 방문자 약 5명에게 '어떤 도구인지 설명하기 / 나에게 맞는 프로젝트 찾기 / 사용 시작하기'를 요청해 막히는 부분을 확인한다. 소규모 관찰은 통계적 성과 검증과 구분한다.

### 3단계: 다시 방문할 이유 만들기 (M)

- [ ] 자료 영역에 세 가지 입문 경로를 넣고 기존 검색·전체 목록을 유지한다.
- [ ] 실제 날짜와 근거가 있는 제작 소식만 최근 3개 정도 노출한다. 표시용으로 날짜만 자동 갱신하지 않는다.
- [ ] 두 번째 체험은 2단계 반응과 사업 목표를 보고 선택한다. 갤러리와 답변 예시를 동시에 추가하지 않는다.
- [ ] 자체 도메인 글이 늘 때만 글 목록·RSS·태그 페이지를 검토한다. 기존 Notion 자료 전체 이전을 선행 조건으로 삼지 않는다.

### 측정: 유료 기능을 전제로 하지 않기

현재 [index.html](D:/mypages/index.html:275)에는 Vercel Analytics와 Speed Insights 로딩이 있다. 그러나 [script.js](D:/mypages/script.js:1)에는 프로젝트 CTA용 사용자 정의 이벤트가 없다. 스크립트가 있다는 사실만으로 어떤 프로젝트가 얼마나 클릭되는지 측정된다고 볼 수 없다.

Vercel 공식 문서는 [Custom Events를 Pro/Enterprise 기능](https://vercel.com/docs/analytics/custom-events)으로 안내한다. [요금제 표](https://vercel.com/docs/analytics/limits-and-pricing)에서도 Hobby의 사용자 정의 이벤트와 UTM 보고서는 제공되지 않는다. 현재 계정 요금제는 이번 조사에서 확인하지 않았으며 자동 업그레이드는 제안하지 않는다.

- [ ] 먼저 필요한 항목을 `project_cta_click(project, location)`, `sample_interaction(project, action)`, `guide_click(topic, source)` 정도로 제한한다.
- [ ] 실제 요금제·예산·개인정보 요구사항에 맞춰 구현 수단을 선택한다. 유료 기능을 사용하지 않으면 사용할 수 없는 지표를 보고서에 약속하지 않는다.
- [ ] 검색 원문, 면접 답변, CSV 내용, 이메일을 이벤트에 넣지 않는다. '클릭'과 하위 서비스의 실제 '사용 완료'는 별개로 측정한다.
- [ ] 방문량과 유입 경로가 비슷한 조건에서 비교한다. 표본이 작을 때 '2주 뒤 전환율 상승' 같은 결론을 내리지 않는다.

## 지금 보류할 것

- 전체 화면 3D, 커서 추적 효과, 자동 재생 영상·음악: 세 서비스로 가는 길보다 눈에 띄게 하지 않는다.
- SNS 피드 자동 임베드: 플랫폼 의존성·로딩 비용이 생긴다. 지금은 선별한 링크와 자체 기록이 적합하다.
- 방문자 로그인, 댓글, 챗봇, 별도 대시보드: 현재 링크 허브 목적에 비해 운영 부담이 크다.
- 근거 없는 고객 후기·사용자 수·수익 인증: 숫자가 준비되지 않았으면 실제 결과물과 제작 판단으로 신뢰를 만든다.
- 단순 유행을 위한 프레임워크 전환: 현재 정적 HTML/CSS/JavaScript로 1~3단계 대부분을 구현할 수 있다.

가장 추천하는 순서: **가독성과 프로젝트 제목 노출 → 작은 체험 하나 → 실제 제작기 한 편 → 입문 경로와 제작 소식**.
