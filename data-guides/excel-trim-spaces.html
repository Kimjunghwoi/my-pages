홈/데이터 실무 가이드/TRIM과 공백

EXCEL · TEXT CLEANUP

TRIM으로 안 지워지는 공백,
같은 빈칸이 아닙니다.

앞뒤가 비어 보이는데 조회가 실패하거나 길이가 예상보다 길다면, 공백의 종류부터 확인하세요. TRIM을 반복해도 바뀌지 않는 값에는 다른 문자가 들어 있을 수 있습니다. 원본 옆에 비교 열을 만들어 원인을 좁혀봅니다.

회몬11년차 개발자 · Column Harbor 운영
2026. 10. 20.
먼저 구분할 것
  1. 일반 공백 32와 NBSP 160은 같은 문자가 아닙니다.
  2. 사람이 읽는 이름과 정확히 보존해야 하는 ID는 정리 규칙이 다릅니다.
  3. 이 수식은 모든 유니코드 공백을 제거하는 만능 해결책이 아닙니다.
이 글에서공백 종류 확인4개 값으로 비교대체 수식 적용ID와 다른 공백실제 계산과 완료 기준

01 / DIAGNOSE

눈으로 보기 전에
문자 코드를 확인합니다

TRIM은 일반 공백인 ASCII 32를 정리합니다. 앞뒤 공백을 없애고 단어 사이의 연속 공백을 한 칸으로 줄입니다. 웹페이지에서 가져온 값에 자주 섞이는 NBSP는 U+00A0, 십진수 160입니다. Microsoft도 TRIM만으로 NBSP를 제거하지 못한다고 TRIM 문서 (새 탭)에서 구분합니다.

A3의 첫 문자가 의심된다면 =UNICODE(LEFT(A3,1))로 읽습니다. 160이면 NBSP이며 32라면 일반 공백입니다. 끝 문자라면 LEFT 대신 RIGHT를 씁니다. 빈 셀에는 이 검사가 오류를 낼 수 있으므로 비어 있지 않은 표본에서 시작하세요. 첫 문자 코드만 같다고 셀 전체가 같다는 뜻도 아닙니다.

02 / REPRODUCE

원본 옆에서
네 가지 값을 나란히 봅니다

빈 시트의 A1에 raw_text를 쓰고 A2:A5에 아래 수식을 각각 입력합니다. 눈에 보이지 않는 문자를 직접 복사하지 않아도 같은 입력을 만들 수 있습니다. 인수 구분자가 세미콜론인 환경에서는 쉼표를 맞춰 바꾸세요.

TSV의 첫 열에는 실제 공백 문자들이 들어 있습니다. 입력 수식으로 만들거나, TSV를 UTF-8·탭 구분·Text로 가져온 뒤 A열 값이 같은지 확인하세요. 파일 가져오기 UI는 이번 실행 검증 범위가 아닙니다. 이 예제의 값은 모두 합성 자료이며 고객 이름이나 실제 상품 코드가 아닙니다.

03 / COMPARE

NBSP를 일반 공백으로 바꾼 뒤
TRIM을 적용합니다

B2에는 =TRIM(A2), C2에는 =TRIM(SUBSTITUTE(A2,UNICHAR(160)," "))를 입력하고 5행까지 채웁니다. SUBSTITUTE의 마지막 인수는 빈 문자열이 아니라 일반 공백 한 칸입니다. 이름 사이의 NBSP를 없애 버리면 SeoulCenter처럼 두 단어가 붙기 때문입니다.

D2에는 =LEN(A2), E2에는 =LEN(B2), F2에는 =LEN(C2)를 입력해 원본·TRIM·대체 후 길이를 비교합니다. G2의 =EXACT(A2,C2)는 대소문자까지 같은지 확인합니다. 길이가 줄었다는 사실만으로 정리가 올바르다고 판정하지 않습니다.

04 / BOUNDARIES

공백을 줄이면
잘못되는 값도 있습니다

A4의 AB 12는 가운데 공백 두 개가 포함된 합성 ID입니다. TRIM 결과는 AB 12로 바뀌고 EXACT는 FALSE가 됩니다. 원본 시스템이 두 값을 다른 키로 취급한다면 정리가 아니라 손상입니다. 표시용 이름을 고치는 규칙을 계정·상품·주문 ID에 그대로 적용하지 마세요.

A5의 U+202F는 코드 8239인 좁은 NBSP입니다. 160만 대체하는 이 수식으로는 남습니다. 코드 8203의 폭 없는 공백 등 다른 문자도 별개의 문제입니다. 문자를 확인하고 업무 규칙에 맞는 대체를 하나씩 정해야 합니다. 한꺼번에 모든 공백을 지우거나 눈에 보이지 않는다는 이유만으로 삭제하면 의미 있는 구분까지 잃습니다.

CLEAN을 추가하면 모두 해결될 것이라고 가정하지도 않습니다. Microsoft CLEAN 문서 (새 탭)는 처리하는 비인쇄 문자 범위를 별도로 설명합니다. 원본 열을 남겨 두고, 바뀐 행 수와 새로 충돌하는 키를 확인한 다음 결과 열만 사용하세요.

05 / VERIFY

수식이 성공한 것과
내 데이터가 안전한 것은 다릅니다

Windows Excel 16.0 build 5574.0의 별도 빈 통합문서에서 위 입력 수식과 TRIM·SUBSTITUTE·LEN·EXACT·UNICODE를 계산했습니다. NBSP 행은 14→14→12, 좁은 NBSP 행은 7→7→7이었고, 합성 ID는 원본과 달라졌습니다. 이 가이드의 원본 문자열과 결과를 실제 셀 값으로 대조했습니다.

이번 검증은 Excel COM 계산입니다.

리본 메뉴 클릭, TSV 붙여넣기/가져오기, 저장 후 재열기나 Mac·웹 Excel을 검증한 결과는 아닙니다. 현재 설치 환경에서 수식이 지원되는지 확인하고 복사본의 표본부터 비교하세요.

  1. 원본과 결과를 함께 보관합니다.새 열에서 정리하고 원본 열을 덮어쓰지 않습니다.
  2. 사라진 것이 어떤 문자였는지 확인합니다.NBSP인지 다른 유니코드 문자인지, 정리 후 단어가 붙지 않았는지 봅니다.
  3. 조회 키의 충돌을 검사합니다.기존에 다른 ID였던 두 행이 같은 값이 되면 정리 기준부터 다시 결정합니다. 병합 결과 행 수·합계도 비교합니다.
