EXCEL · IDENTIFIER PRECISION

16글자인데,
같은 ID가 아니었습니다.

긴 상품 코드가 1.23E+15처럼 보이는 일과 끝자리 자체가 달라진 일은 다릅니다. 열 너비나 표시 서식으로 해결되는지, 이미 원본으로 돌아가야 하는 상태인지 먼저 구분하세요. 식별자라면 숫자로 계산할 필요가 있는지도 다시 확인합니다.

회몬11년차 개발자 · Column Harbor 운영
2026. 10. 20.
원본이 먼저입니다
  1. Excel 숫자는 유효숫자 15자리 정밀도 제한이 있습니다.
  2. 숫자로 변환한 뒤 Text 서식을 줘도 잃은 끝자리는 복원되지 않습니다.
  3. LEN뿐 아니라 ISTEXT와 원본 문자열의 EXACT를 함께 확인합니다.
이 글에서표시와 값 구분16자리 재현 실습원본에서 다시 가져오기브라우저 대안실제 결과와 완료 기준

01 / DISPLAY OR DAMAGE

지수 표시만 보고
손상 여부를 판단하지 않습니다

열이 좁거나 일반 형식을 사용하면 긴 숫자가 지수 표기로 보일 수 있습니다. 표시만 바뀐 경우에는 열을 넓히고 수식 입력줄을 확인하면 원래 값이 남아 있을 수 있습니다. 하지만 유효숫자가 15자리를 넘는 식별자를 숫자로 취급하면서 끝자리가 사라졌다면 표시 형식의 문제가 아닙니다.

Microsoft의 큰 숫자·앞자리 0 안내 (새 탭)도 숫자 정밀도와 텍스트 보존을 구분합니다. 상품 ID처럼 더하거나 평균을 내지 않는 값은 Text를 먼저 검토하세요. 큰 금액·측정값처럼 계산이 필요한 수라면 이 글의 식별자 보존법으로 정밀한 계산까지 해결된다고 보면 안 됩니다.

02 / REPRODUCE

길이는 16으로 같아도
EXACT는 FALSE일 수 있습니다

빈 시트 A2에 =1234567890123456을 입력합니다. B2는 입력 전에 셀 표시 형식을 Text로 지정하고 1234567890123456을 입력합니다. 이 합성 숫자는 실제 고객·계정 번호가 아닙니다. Text 대신 앞에 작은따옴표를 붙여 입력할 수도 있지만, 이미 손상된 셀 뒤에 붙이는 조치는 복구가 아닙니다.

C2에는 =TEXT(A2,"0"), D2에는 =EXACT(C2,B2)를 넣습니다. E2는 =LEN(C2), F2는 =LEN(B2), G2는 =ISTEXT(B2)입니다. TEXT는 현재 숫자를 문자열로 표시할 뿐 원본을 되살리지 않습니다.

같은 길이라는 이유로 검증을 끝내면 이 차이를 놓칩니다. 서로 다른 두 원본이 같은 숫자로 바뀌면 조회나 중복 검사 결과도 달라질 수 있습니다. 표시된 자릿수를 맞추거나 뒤에 0을 추측해 넣는 방법은 원본을 증명하지 못합니다.

03 / IMPORT AGAIN

변환되기 전 원본으로 돌아가
식별자 열만 Text로 지정합니다

CSV가 이미 손상됐다면 덮어쓰지 말고 닫습니다. 수정하지 않은 원본 CSV나 시스템에서 다시 내보낸 파일을 확보하세요. 백업 없이 끝자리를 알아낼 수 없는 상태는 수식으로 복구한다고 약속할 수 없습니다.

  1. Data → From Text/CSV로 원본을 선택합니다.구분자와 인코딩을 확인합니다. 이 예제는 쉼표, 두 열, 데이터 세 행입니다.
  2. Transform Data에서 자동 자료형 변환을 확인합니다.Changed Type 단계가 item_id를 숫자로 바꿨다면 그 단계를 제거한 뒤, 변환 전 값에서 item_id를 Text로 지정합니다. 숫자로 손상된 결과를 다시 Text로 바꾸는 것과 다릅니다.
  3. 수량은 별도로 숫자로 지정합니다.Close & Load 후 item_id 세 문자열을 원본과 대조합니다. quantity 합계는 6이어야 합니다. ID를 합산하거나 숫자로 바꿔 비교하지 않습니다.

일부 최신 Excel에는 Automatic Data Conversions 옵션이 있지만 버전·진입 경로에 따라 다릅니다. 이 글은 해당 옵션이 항상 있거나 모든 가져오기에 적용된다고 가정하지 않습니다. 작업 절차의 기준은 Microsoft의 숫자를 Text로 다루는 안내 (새 탭)와 사용 환경을 함께 확인하세요.

04 / BROWSER ALTERNATIVE

보존용 XLSX가 필요하다면
모든 셀을 Text로 만드는 대안도 있습니다

Column Harbor CSV→Excel 도구 (영문, 새 탭)에 위 CSV를 붙여넣고 Comma로 해석한 뒤 미리보기 세 행과 두 열을 대조할 수 있습니다. XLSX 사본은 브라우저에서 만들어지며 원본 CSV를 덮어쓰지 않습니다. 내려받은 Data 시트에서 item_id 값과 ISTEXT를 확인하세요.

quantity도 Text입니다.

이 경로는 모든 셀을 텍스트로 보존하는 대안입니다. 자동으로 계산용 파일을 완성해주지는 않습니다. 계산하려면 수량 같은 열만 별도 검토해 숫자로 바꿔야 합니다. 이미 1234567890123450으로 바뀐 입력의 끝자리를 복원하지도 않습니다.

05 / OBSERVED RESULT

손상된 값이 아닌
원본 문자열과 대조합니다

Windows Excel 16.0 build 5574.0의 별도 통합문서에서 숫자 리터럴, 미리 Text로 정한 셀, TEXT·LEN·EXACT·ISTEXT를 계산했습니다. 숫자에서 만든 문자열은 1234567890123450, Text 셀은 1234567890123456이었고 둘의 길이는 모두 16이었습니다. EXACT는 FALSE, Text 셀의 ISTEXT는 TRUE였습니다.

실행한 것은 Excel COM의 고정 수식 계산과 Text 셀 값 지정입니다. 리본 메뉴 클릭, CSV 가져오기, 브라우저 도구의 XLSX 내보내기, 저장 후 재열기나 모든 Excel 버전을 이번에 새로 검증한 결과가 아닙니다. 위 가져오기·브라우저 경로를 사용했다면 자신의 결과 파일을 따로 대조해야 합니다.

  1. 첫 행뿐 아니라 값의 충돌도 확인합니다.첫 두 ID의 끝자리가 6과 0으로 구별되고, 세 번째 ID의 앞자리 0이 남아 있어야 합니다.
  2. 문자열과 계산 열을 나눕니다.ID는 정확히 보존하고 quantity만 수치로 검토합니다. LEN만 맞거나 합계만 맞는 것으로 끝내지 않습니다.
  3. 왕복 저장은 별도 확인합니다.CSV에는 Excel 셀 자료형이 저장되지 않습니다. 내보낸 원문에 문자가 남는지 확인하고 다시 가져올 때도 Text 규칙을 적용합니다.
