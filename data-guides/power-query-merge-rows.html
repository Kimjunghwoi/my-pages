홈/데이터 실무 가이드/병합 행 증가

POWER QUERY · MERGE

병합했더니 행과 합계가
늘어났을 때

Left Outer 병합은 왼쪽 행마다 오른쪽의 모든 일치 레코드를 연결합니다. 행 증가가 오류인지 정상적인 one-to-many 관계인지는 보고서가 한 행으로 무엇을 표현해야 하는지에 따라 달라집니다.

회몬11년차 개발자 · Column Harbor 운영
2026. 09. 19.
삭제 전에 확인
  1. 중첩 테이블을 펼치기 전에 키별 매치 수를 셉니다.
  2. 여러 주소·주문처럼 유효한 관계를 중복으로 오해하지 않습니다.
  3. 한 행이 필요하면 명시적인 업무 규칙으로 한 건을 선택합니다.
이 글에서행이 늘어나는 원리펼치기 전 감사관계별 선택Remove Duplicates 주의검증 항목

01 / WHY

병합은 한 건만
골라 주지 않습니다

판매 테이블에 고객 C10의 판매가 두 건 있고 주소 테이블에 C10의 유효한 주소가 두 건 있다면, 고객 ID로 병합한 뒤 주소를 펼칠 때 각 판매가 주소 두 건과 결합됩니다. 판매 두 행이 네 행으로 늘어나는 것은 병합 엔진이 중복을 만든 것이 아니라 요청한 키로 가능한 모든 조합을 보여준 것입니다.

합성 예제에서 판매는 네 건이고 금액 합계는 42입니다. 주소 매치 수가 판매 순서대로 2, 2, 1, 0이라면 펼친 결과는 여섯 행이 됩니다. 반복된 판매 금액을 다시 더하면 72로 보입니다. 이때 72는 새 매출이 아니라 주소를 펼치면서 같은 판매가 반복된 결과입니다.

02 / AUDIT

중첩 테이블 상태에서
매치 수를 확인합니다

병합 직후에는 오른쪽 결과가 중첩 테이블 열에 들어 있습니다. 주소 열 이름이 Addresses라면 Custom Column에 Table.RowCount([Addresses])를 추가해 각 왼쪽 행의 매치 수를 셉니다. 0은 미일치, 1은 단일 일치, 2 이상은 다중 일치입니다.

원래 판매 ID와 매치 수를 함께 남겨 두면 어떤 행이 늘어날지 펼치기 전에 알 수 있습니다. 진단용으로 Keep Duplicates를 사용한다면 원본 조회의 별도 Reference나 복사본에서만 사용합니다. Keep Duplicates 결과는 유일한 키를 제외하기 때문에 생산 병합의 lookup으로 되돌려 쓰면 정상 고객이 사라집니다.

03 / DECISION

원하는 출력의
행 의미를 결정합니다

모든 주소를 보고 싶은 보고서라면 one-to-many 관계를 유지하고 판매 금액을 주소별 새 매출처럼 합산하지 않습니다. 주소 존재 여부만 필요하다면 중첩 테이블을 펼치지 않고 매치 수가 0보다 큰지 계산할 수 있습니다.

판매당 주소 하나가 필요하다면 선택 규칙이 있어야 합니다. 판매 레코드가 address_id를 갖고 있다면 고객 ID 대신 그 키로 연결하는 것이 가장 명확합니다. “현재 주소”를 선택한다면 고객마다 current=true가 정확히 하나인지, 동률과 누락을 어떻게 처리할지 먼저 정의합니다.

행 수를 원래대로 만드는 것은 목표가 아니라 결과입니다.

잘못된 주소 하나를 남겨도 행 수는 맞을 수 있습니다. ID, 미일치 고객, 선택된 주소와 금액을 같이 확인해야 합니다.

04 / CAUTION

정렬 후 Remove Duplicates가
최신 행을 보장한다고 가정하지 않습니다

Power Query의 Table.Distinct는 중복 레코드 중 어느 행이 보존될지 일반적으로 보장하지 않습니다. 단순히 날짜 내림차순 정렬 후 고객 ID 중복을 제거해 최신 주소가 남을 것이라고 믿으면 새로고침이나 쿼리 최적화에서 다른 결과가 생길 수 있습니다.

최신 레코드가 필요하다면 고객별 최대 날짜를 구한 뒤 원본과 다시 매치하고, 같은 최대 날짜가 여러 건인 상황에 tie-break 규칙을 둡니다. 주소 두 개가 모두 실제로 유효하다면 하나를 삭제하지 말고 보고서의 목적에 맞춰 관계를 보존합니다.

05 / VERIFY

판매 4건·합계 42를
여러 각도에서 대조합니다

원본 판매 ID 네 개가 모두 남았는지, 매치 수가 2·2·1·0인지, 펼친 결과가 여섯 행인지 확인합니다. 한 주소 선택 규칙을 적용했다면 선택된 주소 값과 미일치 고객의 null 처리도 봅니다. 마지막으로 보고서가 판매 단위라면 합계가 42인지 대조합니다.

이 예제는 병합 관계를 설명하는 합성 fixture입니다. 실제 Power Query 엔진과 데이터 원본의 folding, privacy level, connector 동작은 환경별로 시험해야 합니다.
