AI 서비스

응답이 돌아온 뒤에도 결과와 사용량이 일치하는지 확인합니다.

  1. 01

    같은 요청을 두 번 보내면?

    격리된 환경에서 같은 요청을 다시 보내고, 실행과 사용량이 중복 반영되지 않는지 확인하세요.

  2. 02

    저장 도중 실패하면?

    결과와 사용량 중 일부만 확정되는 상태가 없는지, 실패 후 다시 조회해 확인하세요.

  3. 03

    완료 응답만 유실되면?

    새 작업을 무조건 시작하지 않고 기존 결과를 확인할 수 있는지 살펴보세요.

  4. 04

    작업이 중간에 멈추면?

    기다림에 끝이 있는지, 만료 안내와 안전하게 다시 시도할 경로가 있는지 확인하세요.

  5. 05

    다른 계정으로 바뀌면?

    이전 사용자의 응답이나 기록이 화면에 돌아오지 않는지 합성 계정으로 확인하세요.

  6. 06

    AI 요청이 제한되면?

    일시 중지·예산 거절을 사용자에게 설명하고, 실패한 요청의 사용량 처리 기준을 확인하세요.

이 질문이 나온 작업 기록 →근거까지 적는 전체 양식 →

ASSET → INQUIRY

웹사이트·콘텐츠

파일이 있는 것과 방문자가 사용할 수 있는 것을 구분합니다.

  1. 01

    실제 주소에서도 자산이 열리나요?

    이미지의 비어 있지 않은 본문과 표시, 다운로드 파일을 공개 주소에서 확인하세요.

  2. 02

    입력을 비우면 어떻게 되나요?

    빈 수량·잘못된 값이 임의의 기본 주문으로 바뀌지 않는지 확인하세요.

  3. 03

    새 탭에서도 선택이 이어지나요?

    샘플·상품 선택이 새 탭과 수정 왕복에서 유지되는지, 연락처가 URL에 없는지 확인하세요.

  4. 04

    문의 전송이 실패하면?

    모의 오류·시간 초과에서 입력 보존과 중복 제출 방지, 대체 문의 경로를 확인하세요.

  5. 05

    샘플의 성격을 정확히 설명하나요?

    AI 예시와 실제 고객 결과를 구분하고, 게시 문구와 납품 범위가 서로 맞는지 확인하세요.

  6. 06

    공개할 파일만 들어 있나요?

    내부 문서·원본 자료·비밀키를 제외하고 공개 빌드만으로 사이트가 동작하는지 확인하세요.

이 질문이 나온 작업 기록 →근거까지 적는 전체 양식 →

실무 가이드

설명, 샘플, 실제 프로그램의 결과가 같은 이야기를 하는지 확인합니다.

  1. 01

    샘플에 문제가 드러나나요?

    합성 입력만으로 설명한 오류와 개선 결과를 비교할 수 있는지 확인하세요.

  2. 02

    예상 결과를 먼저 적었나요?

    실행 전에 예상한 값과 실제 결과를 나란히 기록하고, 차이가 난 조건을 남기세요.

  3. 03

    값뿐 아니라 자료형도 맞나요?

    식별자·0·빈 값·날짜를 구분하고 표시 모양이나 글자 수만으로 통과시키지 마세요.

  4. 04

    실제 프로그램에서 실행했나요?

    엔진·버전·언어·작업 순서를 기록하세요. 독립 계산을 프로그램 실행 증거로 바꾸지 마세요.

  5. 05

    저장한 파일을 다시 열었나요?

    결과 파일을 다시 읽고 원래 값이 보존되는지, 샘플 다운로드가 실제로 되는지 확인하세요.

  6. 06

    미해결·미검증 범위를 적었나요?

    성공한 대체 경로와 원인 해결을 구분하고, 검증하지 못한 환경을 독자에게 알려주세요.
